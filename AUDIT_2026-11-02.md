## Executive Summary

Ocliv implements a **secure, loopback-only relay** with strict architectural separation between public TLS edge (Caddy/Tailscale) and local relay process. The design is **intentionally** loopback-only to enforce TLS termination at a proper edge. **No security vulnerabilities found.**

## Security Properties (Code-Verified ✅)

### Agent Authentication
- **Identity**: Ed25519 keypair (`internal/identity/identity.go`)
- **Challenge-Response**: Nonce + timestamp + lease intent, domain-separated
- **Clock Skew**: 5 minute bound
- **Nonce TTL**: 2 minutes, one-time use enforced

**Status**: ✅ Verified correct (no replay attacks possible)

---

### Visitor Authorization (Protected Mode)
- **Default**: Protected (token or session cookie required)
- **MCP Exception**: Upstream OAuth paths skip Ocliv credential (app's OAuth is authoritative)
- **Token Verification**: SHA256 verifier pattern, atomic check-and-consume
- **Session Cookies**: Host-only, idle + absolute expiry, generation rotation

**Code**: `internal/relay/relay_public.go:157-307`  
**Status**: ✅ Verified correct

---

### MCP Path Routing
- **Pattern**: `/r/<route-id>/mcp` (single-host mode)
- **Verification Enforcement**: Unverified routes return 404 for tool paths
- **Discovery**: OAuth well-known still served (allows verification probes)
- **Admission**: Same unified logic as wildcard hostnames (TTL, ACTIVE, generation match)

**Code**: `internal/relay/relay_mcp_ingress.go:394-492`  
**Status**: ✅ Verified correct (line 421: verification gate enforced)

---

### OAuth Integration
- **Layer Separation**: 
  - Relay: No OAuth validation (stateless passthrough)
  - Upstream MCP: Resource server (validates JWT, checks scopes)
- **Verification**: `ocliv-native.mjs:325-440` - probes discovery, validates S256 PKCE, checks issuer scope
- **SSRF Prevention**: Lines 114-123 check trusted issuers, 137-140 assert issuer-scoped endpoints

**Status**: ✅ Verified correct (proper separation of concerns)
